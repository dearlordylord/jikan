# Working on Jikan

- Keep the engine and workout model pure; consumers own workout state.
- Follow [review rules](docs/code-review.md). Run `npm run check` before handoff.
- Review the whole PR against its base, with independent standards and spec
  reviewers. Fix findings and repeat at least three rounds; explain rejected findings.
- Keep README files brief: one useful example, essential constraints, links.
  Put verification reports in the PR, not the source tree.
- GitHub issues define acceptance criteria; see [tracker](docs/agents/issue-tracker.md).
